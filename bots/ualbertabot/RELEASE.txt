Modified by ShieldBattery on 2026-09-23:
- The packaged configuration is a quiet Terran MarineRush: it disables complete
  map information, user input, debug drawing and output, StrategyIO result
  storage, and opponent-specific strategy overrides.
- In-game chat cannot change the packaged configuration, file paths, or features.
- The external client returns after one completed match. Launch a new process for
  each match.
- The former BOSS/SparCraft timer implementation is not included or compiled.
  The native recipe supplies an independent std::chrono implementation with the
  required public API.
- BWAPI selects its bridge discovery table through SB_BWAPI_INSTANCE and rejects
  malformed identifiers.
- All native targets use the static MSVC runtime.

The package does not calibrate a human skill level. Any external tournament
rating describes a different observed upstream deployment, not this pinned and
modified binary.

Runtime state

The launcher must create a separate writable work directory for every concurrent
bot. The packaged configuration does not enable strategy learning or opponent
result storage. work/bwapi-data/read and work/bwapi-data/write remain writable
only for BWAPI/profile infrastructure. UAlbertaBot_Config.txt in the work directory
holds configuration; keep it intact when resetting the two writable folders.
The bot process is not sandboxed; source review does not create an OS security
boundary.

Experimental compatibility

Use a 1v1 legacy-limit melee game with ShieldBattery's experimental BWAPI 4.4
bridge. This remains a prototype compatibility path, not full BWAPI API
conformance. Public competition eligibility is separate from this package.
